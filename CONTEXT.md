# Service Desk Context Glossary

This glossary defines stable repository code/domain vocabulary. It is not a knowledge index, implementation guide, or session artifact store.

## Repository Code And Domain Terms

| Term                     | Meaning                                                                                                                                                                                      | Source Of Truth                                                                            | Avoid                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| User                     | Authenticated application user represented by the Prisma `User` model. Users can create tickets, be assigned tickets, author notes, and receive roles.                                       | `prisma/schema.prisma`, `lib/access-control.ts`                                            | Account, agent, employee when referring to the model |
| Role                     | Named access grouping represented by the Prisma `Role` model. Roles can be assigned to users and connected to permissions.                                                                   | `prisma/schema.prisma`, admin role actions                                                 | Group, profile                                       |
| Permission               | Section plus operation pair represented by the Prisma `Permission` model. Permissions control access to dashboard/admin sections.                                                            | `prisma/schema.prisma`, `lib/access-control.ts`                                            | Capability unless quoting source text                |
| UserRole                 | Join model assigning a `Role` to a `User`.                                                                                                                                                   | `prisma/schema.prisma`                                                                     | User role text when referring to the model           |
| RolePermission           | Join model granting a `Permission` to a `Role`.                                                                                                                                              | `prisma/schema.prisma`                                                                     | Role permission text when referring to the model     |
| Customer                 | Person or organization contact that requests service, represented by the Prisma `Customer` model.                                                                                            | `prisma/schema.prisma`, ticket flows                                                       | User, requester account                              |
| Asset                    | Trackable hardware, software, or other item that can be linked to tickets, represented by the Prisma `Asset` model.                                                                          | `prisma/schema.prisma`, ticket flows                                                       | Device when category is unknown                      |
| Ticket                   | Service desk work item represented by the Prisma `Ticket` model. Tickets carry status, priority, category, intake channel, customer, optional asset, assignee, creator, notes, and activity. | `prisma/schema.prisma`, `lib/tickets/*`, `app/(dashboard)/tickets/*`                       | Issue when referring to app data                     |
| TicketNote               | User-authored note attached to a ticket.                                                                                                                                                     | `prisma/schema.prisma`                                                                     | Comment when referring to the model                  |
| TicketActivity           | Audit-style event attached to a ticket.                                                                                                                                                      | `prisma/schema.prisma`                                                                     | Log entry when referring to the model                |
| TicketStatus             | Ticket lifecycle enum: `Open`, `InProgress`, `Pending`, `Resolved`, `Closed`.                                                                                                                | `prisma/schema.prisma`                                                                     | State unless quoting UI text                         |
| TicketPriority           | Ticket urgency enum: `Critical`, `High`, `Medium`, `Low`.                                                                                                                                    | `prisma/schema.prisma`                                                                     | Severity unless comparing bug reports                |
| TicketCategory           | Ticket domain enum: `Hardware`, `Software`, `Network`, `Account`, `Other`.                                                                                                                   | `prisma/schema.prisma`                                                                     | Type unless quoting UI text                          |
| IntakeChannel            | How a ticket entered the service desk: `Email`, `Phone`, `Portal`, `Chat`, `WalkIn`.                                                                                                         | `prisma/schema.prisma`                                                                     | Source when referring to the enum                    |
| ActivityType             | Ticket activity enum: `Created`, `StatusChanged`, `PriorityChanged`, `AssigneeChanged`, `NoteAdded`, `AssetLinked`.                                                                          | `prisma/schema.prisma`                                                                     | Event type unless quoting source text                |
| Dashboard Section        | Route-owned area under `app/(dashboard)/`, usually backed by navigation and permission rules.                                                                                                | `app/(dashboard)/`, `docs/agents/knowledge/dashboard-section-permission-flow-checklist.md` | Page group when discussing access control            |
| GitHub Issue Session ID  | Canonical session ID for GitHub-driven workflows. Use the GitHub issue number as `sessions/<issue-number>/`.                                                                                 | `docs/agents/governance.md`, `docs/agents/issue-tracker.md`                                | Branch name, PR number unless explicitly resolved    |
| Session Artifact Package | Local gitignored folder under `sessions/<id>/` containing planning, implementation, testing, review, and handoff artifacts.                                                                  | `docs/agents/governance.md`, `docs/agents/enforcement-spec.md`                             | Knowledge file, source of truth                      |

## Source Boundaries

- Prisma data model source: `prisma/schema.prisma`.
- Access-control source: `lib/access-control.ts` and related tests.
- Ticket domain source: `lib/tickets/*`, `app/(dashboard)/tickets/*`, and Prisma ticket models.
- Dashboard route source: `app/(dashboard)/`.
- Durable agent workflow policy: `AGENTS.md` and `docs/agents/governance.md`.
- Knowledge selection source: `docs/agents/knowledge/README.md`.

## Agentic System Terms

| Term              | Meaning                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Planner           | User-invokable agent that creates session artifacts and approval-ready implementation plans, but does not edit application code.               |
| Implementor       | User-invokable agent that edits code only from an approved implementation plan.                                                                |
| Tester            | User-invokable agent that creates, runs, or assesses test strategy for approved work.                                                          |
| Knowledge Builder | User-invokable agent that refines repository knowledge files, the knowledge index, and glossary candidates without modifying application code. |
| Vision            | User-invokable agent that converts image evidence into deterministic text artifacts for non-vision agents.                                     |
| Contract Auditor  | Hidden read-only agent that checks generated files or handoffs against approved contracts.                                                     |
